Null safety at compile time

Every type is non-nullable unless marked with ?. The compiler analyzes the data-flow to refine the type based on your null checks, so a forgotten null check is a compile-time warning, not a crash.

string? name = getName();
println(name.toLower()); // warning, name may be null
if name {
    println(name.toLower()); // ok, name is non-null here
}

Catches leaks and double-frees in debug builds

Debug builds track every allocation and fail the run at exit if any leaked, reporting how many allocations and bytes went missing. No Valgrind round-trip for the common case.

$ cx run
memory leak: 1 allocation(s), 32 byte(s) leaked

Type-safe tagged unions

Tagged unions via enum, with direct switch matching and type-narrowing. Polymorphism without vtables, allocation, or boilerplate.

switch event {
    case Click: println("fire at ", event.x, ", ", event.y);
    case Keypress: println("move ", event.key);
    case Quit: println(event.x); // error, no 'x' in Quit
}

Zero-allocation iterator chains

Functions like filter, map, chain return pipeable lazy views. End the chain with e.g. sum, any, or a plain for loop and the whole pipeline runs without a single heap allocation.

var total = numbers
    .filter(n => n % 2 == 1)
    .map(n => n * n)
    .sum();
println(total); // 117, zero heap allocations

Import C headers directly

C interop without bindings. Adopt cx file by file next to your existing C/C++ code.

import "SDL3/SDL.h";
SDL_Init(SDL_INIT_VIDEO);
defer SDL_Quit();

Vectors and swizzles

Fixed-size arrays double as vectors: element-wise math, dot products, and GLSL-style swizzle reads and writes. Larger element-wise loops vectorize in release builds.

float[3] pos = [0.0, 10.0, 0.0];
float[3] vel = [3.0, 4.0, 0.0];
vel.y -= 9.8 * dt;
pos += vel * dt;

Zero-config builds

cx run finds every .cx file in your project and directly runs using JIT compilation; no project files or build scripts needed. The build.cx build config file can be added when you need to customize your build.

$ ls
main.cx  util.cx
$ cx build && ./myproject
Hello world

Errors are values

Fallible functions return Result by convention. Callers handle both cases with switch: every error path is visible in the code.

switch makeImage(width, height) {
    case Ok img: println(img.width, "x", img.height);
    case Err e: println("rejected: ", e);
}

Tooling included

cx-lsp language server

Diagnostics as you type, hover signatures, go to definition, completions, find references, and semantic highlighting - in VS Code, Neovim, Emacs, Helix, Zed, anything speaking LSP.

Editor setup →

cx test test runner

Mark a top-level function with @test to make it a unit test, then run them all with cx test. Nothing to install, no boilerplate.

@test
void mathWorks() {
    assert(add(2, 3) == 5);
}
