Leaks caught in debug builds

Debug builds track every allocation and fail the run at exit if any leaked, reporting how many allocations and bytes went missing. No Valgrind round-trip for the common case.

$ cx run game.cx
memory leak: 1 allocation(s), 32 byte(s) leaked

Zero-allocation iterator chains

filter, map, and chain return lazy views, not temporary lists. End the chain with sum, any, or a plain for loop and the whole pipeline runs without a single heap allocation.

var total = numbers.filter(n => n % 2 == 1).map(n => n * n).sum();
println(total); // 117, zero heap allocations

Null safety at compile time

Every type is non-nullable unless marked with ?. Checks narrow automatically, so a forgotten null check is a compile error, not a crash.

int? bonus = lootBonus();
println(bonus + 1); // error: no matching
//   operator '+' with arguments 'int?' and 'int'
if bonus {
    println(bonus + 1); // OK: narrowed to int
}

Errors are values

Fallible functions return Result. Callers handle both cases with switch: every error path is visible in the code.

switch makeImage(width, height) {
    case Ok img: println(img.width, "x", img.height);
    case Err e: println("rejected: ", e);
}

Import C headers directly

C interop without bindings. Adopt cx file by file next to your existing C code.

import "SDL3/SDL.h";
SDL_Init(SDL_INIT_VIDEO);
defer SDL_Quit();

Vectors and swizzles

Fixed-size arrays double as vectors: element-wise math, dot products, and GLSL-style swizzle reads and writes. Larger element-wise loops vectorize in release builds.

float[3] pos = [0.0, 10.0, 0.0];
float[3] vel = [3.0, 4.0, 0.0];
vel.y -= 9.8 * 0.016; // gravity
pos += vel * 0.016;   // integrate

Type-safe tagged unions

Tagged unions with direct switch matching. Dispatch input events with no vtables, no allocation, no boilerplate.

switch event {
    case Click: println("fire at ", event.x, ", ", event.y);
    case Keypress: println("move ", event.key);
    case Quit: println("bye");
}

Zero-config builds

cx run finds every .cx file and JIT-compiles straight to execution - no project files, no build scripts. A build.cx only appears when you need dependencies or link settings, and it is plain cx.

$ ls
main.cx  util.cx
$ cx build && ./myproject
Hello world

Tooling included

New languages usually mean printf debugging. cx ships a language server from day one.

cx-lsp language server

Diagnostics as you type, hover signatures, go to definition, completions, find references, and semantic highlighting - in VS Code, Neovim, Emacs, Helix, Zed, anything speaking LSP.

cx test test runner

Mark a top-level function with @test to make it a unit test, then run them all with cx test. Nothing to install, no boilerplate.

@test
void mathWorks() {
    assert(add(2, 3) == 5);
}
